# Frontend UX

## Student App

- Dashboard
- Grade/subject/chapter catalog
- Concept page
- Simulation workspace
- Formula library
- Practice area
- Progress page
- Subscription page
- Profile and session/device management

## Simulation Workspace

Desktop layout:

- Left: simulation canvas
- Right: controls and scenario presets
- Lower or side tabs: formula, graph, calculation, explanation, practice

Mobile layout:

- Canvas first
- Controls in drawers
- Large sliders, steppers, and number inputs
- Formula/practice tabs below

## Teacher App

- Presentation mode
- Groups/classes
- Assign simulations or practice
- View student progress
- Share lesson links

## Institution Portal

- Organization dashboard
- Students and teachers
- Seat licenses
- Bulk invite/import
- Usage reports
- Billing and invoices

## Staff Admin

Use a dense, work-focused dashboard style with tables, filters, review queues,
preview panels, version history, and audit trails.

## Student Dashboard

Must show:

- Current class/subject path.
- Continue learning.
- Recent simulations.
- Progress by subject.
- Weak topics.
- Subscription status.

## Concept Page

Must show:

- Breadcrumb.
- Concept objective.
- Source/chapter reference.
- Available simulations.
- Formula cards.
- Practice entry.
- Progress state.
- Language toggle.

## Simulation Workspace

Required UI regions:

- Visual model/canvas.
- Controls panel.
- Scenario presets.
- Output metrics.
- Formula panel.
- Step-by-step calculation panel.
- Graph/diagram panel where relevant.
- Practice mode.
- Explanation/common mistakes.
- Reset, save, fullscreen/presentation actions.

## Admin UX

Admin should prioritize speed and clarity:

- Tables for large data.
- Status filters.
- Review queues.
- Sticky action bars.
- Side-by-side preview and configuration.
- Autosave draft indicators.
- Explicit publish/rollback controls.

## Responsive Rules

- Desktop can use split panes.
- Tablet can keep canvas and controls side by side when space allows.
- Mobile should stack canvas, controls, formula, and practice in tabs/drawers.
- Inputs must have large touch targets.
- Text must not overflow cards, buttons, or tables.
